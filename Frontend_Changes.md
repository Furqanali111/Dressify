# Frontend Updates Required for Advanced AI Recommendations

Based on the new requirements for the AI Feedback and Recommendation flow, several updates need to be made to the frontend UI and UX.

## 1. AI Recommendation Window (New Screen / Modal)
Currently, AI feedback is tied to an existing try-on session. We need a new dedicated window/screen for "Get AI Recommendations".
* **Entry Point:** A new button on the Home or Wardrobe screen (e.g., "Style Me" or "What should I wear?").
* **Inputs:** 
  * Allow the user to select an existing saved outfit to get feedback on.
  * **OR** allow the user to upload a new picture of themselves wearing an outfit directly into this window.
  * Allow the user to input the "Occasion" (e.g., Wedding, Casual Hangout, Date Night).
* **Location Permission:** Since the AI now provides weather-aware styling, the app must request Location Permissions to send the user's `latitude` and `longitude` to the backend. If denied, the AI will still work but will lack weather context.

## 2. Handling New Uploads from the AI Window
If the user uploads a new picture of themselves wearing an outfit specifically for AI feedback:
* **Backend Implication:** The frontend needs to send this image to the backend. If this contains new clothing items that aren't in their wardrobe, we need a flow to process, background-remove, and save these items to their wardrobe so the AI can reference them in the future.
* **UI Update:** Show a prompt: *"We noticed new clothing items in this photo. Would you like to save them to your wardrobe?"*

## 3. Visualizing AI Recommendations
When the AI suggests pairing the current outfit with a different item from the user's wardrobe (e.g., "Swap your top with your Blue Button-Down Shirt").
* **UI Update:** The AI suggestion card should include a **"Visualize"** button.
* **Action:** Clicking this button should automatically swap the recommended item onto the 2D Avatar in the Try-On canvas.
* **Backend Implication:** The AI JSON response schema needs to be updated to return the exact `clothing_item_id` of the recommended wardrobe item. The frontend can then fetch this ID and overlay it on the avatar.

## 4. Wardrobe Metadata & Naming
Currently, the AI only knows what the clothing item looks like based on its **Name** and **Type**. It does not automatically see the image during the feedback phase.
* **UI Update:** Encourage the user to be descriptive when naming items during upload (e.g., "Red Striped T-Shirt" instead of just "Shirt").
* **Future Enhancement:** We can update the backend upload pipeline to automatically use AI Vision to tag the uploaded clothing with colors, prints, and styles (e.g., `color: blue`, `pattern: striped`) so the user doesn't have to type it manually. This metadata will then be fed to the styling AI.

## 5. Auto-Outfit Generation ("Style Me" Feature)
We have added a new backend endpoint (`POST /outfits/generate`) that automatically builds an outfit for the user based on their wardrobe, occasion, and live weather.
* **UI Update:** Add a prominent "Auto-Style" or "Generate Outfit" floating action button (FAB) or banner on the Wardrobe screen.
* **UX Flow:** 
  1. User taps "Auto-Style".
  2. A clean, glassmorphic bottom sheet slides up asking:
     * *Occasion:* Dropdown or chips (e.g., Casual, Work, Date, Party).
     * *Must-wear item (Optional):* User can select a specific item they definitely want to wear today.
  3. The frontend must **request Location Permissions** if not already granted. It fetches the user's coordinates (latitude/longitude) via device APIs to pass to the backend (for weather context).
  4. While generating, show a dynamic loading animation (e.g., "AI is checking the weather...", "Scanning your wardrobe...").
  5. Upon success, the 2D Try-On canvas automatically updates with the fully matched outfit generated by the AI.
* **Theme Considerations:** Use the premium dark mode palette, smooth gradients on the FAB, and micro-animations for the loading states to wow the user.
